# 验证记录

本记录描述已执行的定向验证和仍需验证的边界，不代表所有硬件或 Windows 版本都已覆盖。模拟故障使用隔离数据；实机升级前会备份现有历史与设置。

## 已执行

- 在 Windows 11 x64 上构建桌面应用、采集服务和共享核心；界面通过隔离实例检查中英文即时切换、重启后语言保留、设置分组切换和未保存草稿保留。
- 在独立进程中对总览、设置和用电记录进行深浅主题的离屏渲染检查，并检查 900 × 640 最小窗口的核心指标；测试数据为人工生成，这不代替真实桌面及不同缩放比例的检查。
- 隔离 SQLite 场景覆盖事务失败与重试、断连及来源切换、功率缺失、同次开机恢复、模拟断电重启、跨午夜睡眠、费率生效、时钟回拨、覆盖区间压缩和旧库升级。未知时段不补算电量。
- 对非有限数值及负功率进行了定向检查：无效的 CPU 或独显功率不会被标记为完整读数。
- 在一轮短时隔离运行中记录 224 次采样，最长间隔约 1.9 秒；该结果不代表长期满载或全天运行表现。
- 使用独立命名管道模拟采集服务断开，检查了服务采样 → 本机回退 → 服务恢复的顺序；验证副本缩短了重试等待并替换了服务身份校验，不能代替正式服务的端到端测试。
- 更新资产检查包含签名正确与篡改、路径越界、链接和目录切换中断的隔离场景；完整升级仍需在具备管理员权限的环境验证。
- 自动更新另使用临时签名密钥、独立服务与 HKCU 测试项验证了管理员进程 READY 握手、短时锁释放后的自动回滚，以及持续锁下保留备份和恢复任务；未覆盖正式 HKLM 或真实重启。
- 匿名 GitHub API 主配额耗尽时，使用固定仓库的发布页发现版本并验证公钥签名；已在真实限流环境及隔离的恶意跳转、签名篡改和版本回退场景中检查。
- 手动升级在隔离目录内模拟了逐文件中断和清理中断，并用独立 Windows 服务验证了提交与回滚后恢复原服务状态；未改动正式服务。
- 采集服务修复在独立 Windows 服务上验证了运行中重启、停止后启动、禁用时拒绝，以及文件哈希、权限和事务冲突的保护。
- 在 Windows 11 x64 上将现有 0.2.1 原位升级至 0.3.0；检查了历史库完整性、新记录写入、原电价、登录自启、PawnIO、采集服务、桌面快捷方式与单实例唤回。
- 随后原位升级至 0.3.1，从设置页面触发了实际采集服务修复，确认服务重新启动、应用进程持续运行，并从临时本机采集自动切回硬件服务。
- 实机安装后设置页报告任务栏已嵌入，预览包含 CPU、GPU 占用和功率；这不代表已完成与其他组件的目视共存验证。
- 0.3.0 一次约 128 秒的后台采样中，应用和服务合计平均 CPU 约 0.36%，私有工作集平均约 153 MiB、峰值约 162 MiB；这不是高负载或长时间运行的保证。
- 0.3.1 一次约 69 秒的后台复测中，应用和服务合计平均 CPU 约 0.35%，私有工作集平均约 145 MiB、峰值约 156 MiB。
- 0.3.1 打开总览的约 20 秒测量中，应用和服务合计平均 CPU 约 0.49%，结束时私有工作集合计约 142 MiB；排行和快览的前台资源占用尚未完成实测。

## 仍需关注

- 实体休眠、休眠唤醒、异常断电与真实系统重启，以及连续隔夜运行。
- Windows 任务栏不同布局、与其他任务栏组件共存、Explorer 重启、自隐藏以及多显示器不同 DPI。
- 100%、150%、200% 缩放下的逐页真实桌面视觉检查。当前测试环境的窗口截图未能正常捕获 WPF 内容，不能据此宣称视觉验收完成。
- 采集服务和应用合计的长期 CPU、私有工作集，以及 AI 绘图、视频生成等高负载下的持续采样。
- 自动更新的受保护安装目录、服务切换和真正开机恢复端到端验证。RunAs 能获得管理员令牌，但在本机创建独立 HKLM 测试项时被系统拒绝，应用内安装保持关闭。

一次性测试工程和数据应在完成后清理；保留长期测试用例需满足项目的测试约定。
